# Описание схемы работы сети CloudBox

## 1. Что должна показывать схема

Для проекта CloudBox нужна одна блок-схема сетевого взаимодействия
клиент-серверного веб-приложения. На ней не требуется подробно показывать
регистрацию, корзину, переименование файлов, административную панель и другие
внутренние функции программы.

Главная задача схемы: показать, как браузер устанавливает соединение с
веб-сервером Flask, передает HTTP-запрос, получает HTTP-ответ и завершает либо
продолжает сетевой обмен.

При локальном запуске сервер доступен по адресу:

```text
http://127.0.0.1:5001
```

Здесь:

- `127.0.0.1` - IP-адрес loopback-интерфейса локального компьютера;
- `5001` - TCP-порт, который веб-сервер прослушивает по умолчанию;
- `HTTP` - протокол прикладного уровня;
- `TCP` - транспортный протокол, обеспечивающий надежную передачу данных;
- `IP` - сетевой протокол, обеспечивающий адресацию и доставку пакетов.

Если приложение будет размещено на другом компьютере, вместо `127.0.0.1`
используется IP-адрес или доменное имя сервера. Общий алгоритм работы сети при
этом не меняется.

Порт можно изменить через переменную окружения `PORT`. На схеме следует
оставить значение `5001`, так как именно оно используется программой по
умолчанию.

## 2. Название листа

В основной надписи указать:

```text
Веб-приложение облачного файлового хранилища CloudBox
Схема алгоритма сетевого взаимодействия
```

Лист расположить горизонтально. Оформление выполнить по аналогии с
предоставленным примером: рамка, основная надпись в правом нижнем углу,
прямоугольники операций, ромбы условий, овалы начала и конца, круглые
соединители с одинаковыми номерами.

## 3. Общая компоновка листа

Разделить рабочее поле на три части:

1. Левая часть: запуск сервера и переход к ожиданию подключения.
2. Центральная часть: прием TCP-соединения, получение HTTP-запроса и выбор
   типа сетевого обмена.
3. Правая часть: отправка HTTP-ответа клиенту и завершение либо продолжение
   TCP-соединения.

В нижней части листа разместить небольшую поясняющую схему уровней сети.

Упрощенное расположение:

```text
ЛЕВАЯ ЧАСТЬ              ЦЕНТРАЛЬНАЯ ЧАСТЬ                  ПРАВАЯ ЧАСТЬ

Начало                   Соединитель 1
  |                           |
Запуск сервера            Принятие TCP-соединения
  |                           |
Привязка к IP             Получение HTTP-запроса
и порту 5001                  |
  |                       Разбор запроса
Прослушивание                 |
TCP-порта                 Тип HTTP-обмена?
  |                           |
Соединитель 1            Ветви обработки ----------------> Соединитель 2
                                                             |
                                                         Отправка ответа
                                                             |
                                                         Продолжить TCP-
                                                         соединение?
                                                          /          \
                                                        Да            Нет
                                                        |              |
                                               Новый HTTP-запрос   Закрытие TCP-
                                                                  соединения
                                                                      |
                                                               Соединитель 1
```

## 4. Левая часть: запуск сервера

В левой части листа разместить одну вертикальную цепочку блоков.

Сверху вниз:

1. Овал:

   ```text
   Начало
   ```

2. Прямоугольник:

   ```text
   Запуск Flask-приложения
   CloudBox
   ```

3. Прямоугольник:

   ```text
   Привязка веб-сервера
   к IP-адресу и TCP-порту 5001
   ```

4. Прямоугольник:

   ```text
   Прослушивание TCP-порта
   и ожидание подключения клиента
   ```

5. Круглый соединитель:

   ```text
   1
   ```

Между всеми блоками провести вертикальные стрелки сверху вниз.

## 5. Центральная часть: получение запроса

В верхней части центральной колонки разместить круглый соединитель:

```text
1
```

От него провести вертикальную стрелку вниз к следующим блокам:

1. Прямоугольник:

   ```text
   Принятие TCP-соединения
   от клиентского браузера
   ```

2. Прямоугольник:

   ```text
   Получение HTTP-запроса
   ```

3. Прямоугольник:

   ```text
   Разбор HTTP-запроса:
   метод, URL, заголовки,
   cookie сессии, тело запроса
   ```

4. Ромб:

   ```text
   Тип сетевого обмена?
   ```

От ромба вывести пять ветвей. Расположить их в нижней центральной части листа
слева направо:

1. Получение веб-страницы.
2. Отправка данных формы.
3. Загрузка файла на сервер.
4. Скачивание файла с сервера.
5. Ошибочный запрос.

После выполнения каждой ветви линии объединяются в нижний круглый
соединитель:

```text
2
```

## 6. Ветка 1: получение веб-страницы

Подпись над стрелкой от ромба:

```text
GET-запрос страницы
```

Ниже разместить вертикально:

1. Прямоугольник:

   ```text
   Получение URL
   и параметров запроса
   ```

2. Прямоугольник:

   ```text
   Формирование HTML-страницы
   ```

3. Прямоугольник:

   ```text
   HTTP-ответ:
   статус 200 OK,
   HTML-содержимое
   ```

После этого провести линию к соединителю `2`.

Рядом с ветвью добавить примечание:

```text
После получения HTML браузер может отправить
отдельные GET-запросы для CSS, логотипа и favicon.
Каждый запрос проходит тот же сетевой цикл.
```

## 7. Ветка 2: отправка данных формы

Подпись над стрелкой от ромба:

```text
POST-запрос формы
```

Ниже разместить вертикально:

1. Прямоугольник:

   ```text
   Получение полей формы
   и cookie сессии
   ```

2. Прямоугольник:

   ```text
   Обработка запроса
   веб-приложением
   ```

3. Прямоугольник:

   ```text
   HTTP-ответ:
   redirect 302
   или HTML-страница
   ```

После этого провести линию к соединителю `2`.

Рядом с ветвью добавить примечание:

```text
После redirect 302 браузер автоматически
отправляет новый GET-запрос по адресу Location.
```

## 8. Ветка 3: загрузка файла на сервер

Подпись над стрелкой от ромба:

```text
POST /upload
```

Ниже разместить вертикально:

1. Прямоугольник:

   ```text
   Получение multipart/form-data:
   параметры формы и байты файла
   ```

2. Прямоугольник:

   ```text
   Передача байтов файла
   по TCP-соединению
   ```

3. Прямоугольник:

   ```text
   Сохранение принятого файла
   на диске сервера
   ```

4. Прямоугольник:

   ```text
   HTTP-ответ:
   redirect 302
   и сообщение о результате
   ```

После этого провести линию к соединителю `2`.

В этой схеме не нужно подробно показывать внутренние проверки имени файла,
размера и пользовательской квоты. Достаточно подписать рядом с блоком
сохранения:

```text
Внутри приложения выполняются проверки
размера файла и доступного места.
```

## 9. Ветка 4: скачивание файла с сервера

Подпись над стрелкой от ромба:

```text
GET /download/<file_id>
```

Ниже разместить вертикально:

1. Прямоугольник:

   ```text
   Проверка наличия файла
   на сервере
   ```

2. Ромб:

   ```text
   Файл найден?
   ```

От ромба вывести две стрелки:

- `Да` - вниз;
- `Нет` - вправо, к ветке ошибочного запроса.

По ветви `Да` разместить:

3. Прямоугольник:

   ```text
   Формирование HTTP-ответа:
   заголовки скачивания
   и байты файла
   ```

4. Прямоугольник:

   ```text
   Передача файла клиенту
   по TCP-соединению
   ```

После этого провести линию к соединителю `2`.

Рядом с блоком формирования ответа добавить:

```text
Content-Disposition: attachment
```

Это показывает, что браузер получает файл для скачивания.

## 10. Ветка 5: ошибочный запрос

Подпись над стрелкой от ромба:

```text
Ошибка
```

Ниже разместить вертикально:

1. Прямоугольник:

   ```text
   Формирование сообщения
   об ошибке
   ```

2. Прямоугольник:

   ```text
   HTTP-ответ:
   страница ошибки
   или redirect
   ```

После этого провести линию к соединителю `2`.

Рядом с ветвью перечислить примеры:

```text
404 Not Found
413 Request Entity Too Large
redirect на страницу входа
```

## 11. Правая часть: отправка ответа и завершение обмена

В нижней части после объединения всех ветвей разместить круглый соединитель:

```text
2
```

От него провести линию вправо и затем вверх к следующей вертикальной цепочке:

1. Прямоугольник:

   ```text
   Отправка HTTP-ответа
   клиентскому браузеру
   ```

2. Ромб:

   ```text
   TCP-соединение
   используется повторно?
   ```

От ромба вывести две ветви.

Ветка `Да`:

1. Прямоугольник:

   ```text
   Ожидание следующего
   HTTP-запроса клиента
   ```

2. Стрелка возвращается к блоку:

   ```text
   Получение HTTP-запроса
   ```

Ветка `Нет`:

1. Прямоугольник:

   ```text
   Закрытие
   TCP-соединения
   ```

2. Стрелка возвращается к соединителю:

   ```text
   1
   ```

После возврата сервер снова ожидает подключение клиента. Таким образом,
основной алгоритм работает циклически.

Рядом с ромбом добавить примечание:

```text
Повторное использование и закрытие TCP-соединения
выполняются HTTP-сервером автоматически.
```

## 12. Поясняющая схема уровней сети

В нижней свободной части листа разместить небольшую горизонтальную схему.
Она не соединяется стрелками с основным алгоритмом и служит пояснением.

```text
+----------------------+       +----------------------+       +----------------------+
| Клиентский браузер   |       | Сеть или loopback    |       | Сервер CloudBox      |
|                      |       |                      |       |                      |
| HTTP-запрос           | ----> | TCP-сегменты         | ----> | Flask/Werkzeug       |
| HTTP-ответ            | <---- | IP-пакеты            | <---- | TCP-порт 5001        |
+----------------------+       +----------------------+       +----------------------+
```

Под схемой подписать уровни:

```text
Прикладной уровень: HTTP
Транспортный уровень: TCP
Сетевой уровень: IP
Интерфейс при локальном запуске: loopback 127.0.0.1
```

## 13. Что не нужно добавлять на схему

На схеме сетевого взаимодействия CloudBox не следует показывать:

- базу данных;
- запросы к внешним серверам;
- DNS-разрешение адреса при локальном обращении к `127.0.0.1`;
- ручную работу приложения с сокетами;
- проверку `ETag`;
- заголовок `Range`;
- ответ `206 Partial Content`;
- потоковое воспроизведение аудио или видео.

Эти элементы отсутствуют в программе CloudBox.

## 14. Краткий список блоков для переноса в редактор

Основной поток:

```text
Начало
-> Запуск Flask-приложения CloudBox
-> Привязка веб-сервера к IP-адресу и TCP-порту 5001
-> Прослушивание TCP-порта и ожидание подключения клиента
-> [1]
-> Принятие TCP-соединения от клиентского браузера
-> Получение HTTP-запроса
-> Разбор HTTP-запроса
-> <Тип сетевого обмена?>
-> одна из пяти ветвей
-> [2]
-> Отправка HTTP-ответа клиентскому браузеру
-> <TCP-соединение используется повторно?>
```

Возвраты:

```text
Да
-> Ожидание следующего HTTP-запроса клиента
-> Получение HTTP-запроса

Нет
-> Закрытие TCP-соединения
-> [1]
```
